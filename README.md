# Seor FACEIT — Discord-бот для матчей Standoff 2

Самостоятельная реализация бота по логике из референс-видео. Внешний вид и названия немного изменены, но основной сценарий сохранён.

## Что умеет

- четыре лиги: **Default / Qualifications / Division / Pro**;
- отдельные очереди `ranked` и голосовые `Lobby`;
- автоматическое добавление игрока в очередь при входе в голосовой канал;
- запуск матча при наборе 10 игроков и случайное деление 5×5;
- закрытые голосовые комнаты команд CT и T;
- случайный выбор карты и хоста;
- карточка матча с составами и единственной кнопкой `Получить ID`;
- автоматическая выдача Standoff 2 ID хоста одной кнопкой;
- приём результата `13:Х`, начисление рейтинга и статистики;
- профиль игрока и привязка Standoff 2 ID;
- изображение топ-10 игроков;
- создание личной голосовой комнаты и управление названием, лимитом, доступом и видимостью;
- отправка результата в два шага: ID/счёт, затем скриншот игры;
- закрытый админ-канал проверки с кнопками «Принять» и «Отклонить»;
- ручная регистрация результата администрацией;
- тикеты поддержки;
- интерактивный дашборд с понятными исходными названиями: «Статистика», «Рейтинг», «Матчи», «Пати», «Аккаунт», «Профиль» и «Топ сервера»;
- создание, выдача и снятие ролей Owner, Admin и отдельного Curator для каждой лиги через дашборд;
- закрытый командный канал и временное ограничение slash-команд для пользователей без служебных ролей;
- команда `/delete` для удаления всей структуры, созданной ботом;
- полная структура каналов из видео, включая пока пустые разделы;
- SQLite — данные не пропадут после перезапуска.

> Это новый код, написанный с нуля по видимому поведению интерфейса. Чужой исходный код, логотипы и закрытые материалы не копировались.

## 1. Создание приложения Discord

1. Открой [Discord Developer Portal](https://discord.com/developers/applications).
2. Нажми **New Application**, укажи название.
3. Перейди в **Bot** → **Add Bot**.
4. Включи **Server Members Intent** и **Message Content Intent**. Voice State intent доступен по умолчанию.
5. Нажми **Reset Token**, скопируй токен и никому его не отправляй.
6. В **OAuth2 → URL Generator** выбери:
   - scopes: `bot`, `applications.commands`;
   - bot permissions: `Manage Channels`, `Manage Roles`, `Move Members`, `View Channels`, `Send Messages`, `Embed Links`, `Attach Files`, `Read Message History`, `Connect`, `Speak`.
7. Открой сгенерированную ссылку и добавь бота на сервер.

Рекомендуется дать боту роль выше обычных пользовательских ролей. Иначе перенос игроков и настройка закрытых каналов могут не работать.

## 2. Быстрый запуск на Windows

Установи Python 3.11–3.13 и выполни в папке проекта:

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
notepad .env
py bot.py
```

В `.env` вставь токен и ID тестового сервера:

```env
DISCORD_TOKEN=токен_бота
GUILD_ID=123456789012345678
BOT_NAME=Seor FACEIT
ACCENT_COLOR=7C3AED
```

Чтобы скопировать ID сервера, включи **Настройки Discord → Расширенные → Режим разработчика**, затем нажми правой кнопкой на сервер → **Копировать ID**.

## 5. Развёртывание на Railway

1. Создай новый пустой репозиторий GitHub и загрузи в него содержимое папки проекта (не сам ZIP).
2. Открой [Railway](https://railway.com/), нажми **New Project → Deploy from GitHub repo** и выбери репозиторий.
3. В сервисе открой **Variables** и добавь:
   - `DISCORD_TOKEN` — токен Discord-бота;
   - `GUILD_ID` — ID сервера;
   - `BOT_NAME` — `Seor FACEIT`;
   - `ACCENT_COLOR` — например `7C3AED`;
   - `LOBBY_SIZE` — число игроков для запуска матча: `10` для работы или `1` для одиночного теста;
   - `QUALIFICATION_KD` — норматив квалификации, по умолчанию `1.00`;
   - `GEMINI_API_KEY` — ключ Gemini API для фона профиля;
   - `GEMINI_IMAGE_MODEL` — `gemini-2.5-flash-image`;
   - `GEMINI_VISION_MODEL` — `gemini-3.6-flash` для чтения скриншотов;
   - `PROFILE_IMAGE_PROMPT` — описание желаемого оформления профиля.
4. Для постоянной базы добавь **Volume** и укажи путь монтирования `/app/data`.
5. Нажми **Deploy**. Команда запуска уже задана в `railway.json` и `Procfile`.
6. В логах должна появиться строка `... ready`. После этого выполни `/setup` в Discord.

Важно: бесплатного постоянно работающего тарифа у Railway может не быть; стоимость зависит от текущего тарифа аккаунта.

## 6. Первичная настройка сервера

1. Запусти бота.
2. На сервере выполни команду `/setup` от имени администратора. Команда синхронизирует управляемые ботом категории: добавляет отсутствующие каналы, удаляет лишние внутри них и заменяет категории старых тестовых версий на фирменную структуру SEOR. Посторонние пользовательские категории она не затрагивает.
3. Бот создаст собственную структуру SEOR: `📡 SEOR INFO`, `⌨️ SEOR COMMANDS`, `💬 SEOR COMMUNITY`, `🆘 SEOR SUPPORT`, `🎧 SEOR PRIVATE`, `📮 SEOR RESULTS`, закрытый `🛡️ SEOR STAFF` и по три Lobby для каждой из четырё���� лиг.
4. Новый игрок открывает `📋・регистрация` и в одной форме вводит игровой ник и Standoff 2 ID; после выдачи роли канал регистрации исчезает.
5. Игроки заход��т в нужный `Lobby 1`. При 10 ��част����ках матч создаётся автоматически.
6. Выбранный хост создаёт лобби в игре.
7. После распика доступна кнопка **Получить ID**. Любой участник матча нажимает её и автоматически получает Standoff 2 ID хоста, который хост указал при регистрации. Ничего дополнительно вводить не нужно.
8. Для результата игрок нажимает кнопку **Отправить результат**. Открывается форма, где нужно указать только номер матча и прикрепить полный скриншот итоговой таблицы. Счёт, карту и K/D/A/MVP бот считывает автоматически — вручную счёт вводить нельзя.
8. Заявка появится в закрытом канале `проверка-результатов`. Администратор нажимает **Принять** или **Отклонить**; принятый матч публикуется в `история-игр` и обновляет рейтинг.

## Регистрация новых игроков

После `/setup` создаются категория `▶️ SEOR START`, единственный канал `📋・регистрация` и роль `зарегистрирован`.

- новый участник без роли видит только канал регистрации;
- бот также отправляет личную приветственную карточку в дизайне SEOR;
- новый игрок нажимает **Регистрация** и в одной форме вводит игровой ник и Standoff 2 ID;
- игрок со старым профилем нажимает **Войти по данным**, вводит прежний ник и Standoff 2 ID, после чего бот восстанавливает профиль и статистику;
- после проверки формата ID бот сохраняет профиль и выдаёт роль `зарегистрирован`;
- канал регистрации скрывается, а основные разделы сервера открываются;
- закрытые лиги по-прежнему требуют отдельную роль лиги.

Игроки, у которых Game ID уже был сохранён в базе предыдущей версии, получат роль автоматически во время `/setup`. Для работы личного приветствия должен быть включён **Server Members Intent**. Роль бота должна стоять выше роли `зарегистрирован`.

## Закрытый штаб

Сохраняются закрытые категории `🛡️ SEOR STAFF` и `📡 SEOR AUDIT` с каналами штаба, санкций, доказательств, регистрации игр и журналов. Категория `🚨 SEOR PRIORITY` и канал приоритетных тикетов удаляются командой `/setup`.

## Доступ к чатам лиг

Лиговые чаты закрываются отдельно:

- `чат-pro` — только роль `pro League`;
- `чат-division` — только роль `division League`;
- `чат-qualifications` — только роль `qualifications League`;
- `чат-кураторов` — только `PRO League curator`, `division curator`, `qualifications curator`, `owner` и `admin`.

Общие чаты остаются открытыми. Профили не скрываются по лигам: любой игрок может открыть профиль участника любой лиги через `/profile member` или поиск по игровому ID в дашборде.

## Автоматическая картинка профиля через Gemini

В Railway → **Variables → Raw Editor** добавь:

```env
GEMINI_API_KEY=ТВОЙ_КЛЮЧ_GEMINI
GEMINI_IMAGE_MODEL=gemini-2.5-flash-image
PROFILE_IMAGE_PROMPT=Dark competitive esports profile background, black and deep violet, clean negative space, no text, no logos
```

Команда `/profile` создаёт персональную карточку: цвета, подсветка, рамки и фон автоматически подбираются из аватарки игрока. В верхней части отдельными блоками показаны участник, Standoff 2 ID, лига и ELO. Ниже находятся общая статистика, прогресс лиги, последние матчи и показатели по картам. В карточку встроен логотип SEOR.

После изменения переменных сделай Railway Redeploy. Первая генерация может занять несколько секунд и расходует квоту Gemini API.

## Автоматическое чтение и регистрация скриншотов

Игрок нажимает кнопку **Отправить результат**. В открывшейся форме он указывает номер матча и загружает скриншот итоговой таблицы. Поля для ручного ввода счёта нет. Gemini Vision автоматически извлекает:

- итоговый счёт;
- карту;
- ники игроков;
- kills, deaths, assists и MVP;
- уверенность распознавания.

Если уверенность не ниже 55% и счёт ��орректен, распознанный счёт исполь��уется как предложенный результат. Заявка вместе со скриншотом и распознанной статистикой отправляется в закрытый канал `регистрация-игр`. Admin/Owner или куратор соответствующей лиги нажимает **Принять** либо **Отклонить**. Только после подтверждения обновляются результат, ELO, K/D/A и MVP. Нераспознанные ники помечаются предупреждением и не изменяют статистику автоматически.

Для функции нужна переменная `GEMINI_VISION_MODEL=gemini-3.6-flash` и тот же `GEMINI_API_KEY`.

## Распик и автоматический бан карт

После заполнения Lobby — при `LOBBY_SIZE=1` для теста или `LOBBY_SIZE=10` для обычного матча — запускается первоначальный фиолетовый дизайн **РАСПИК КАРТ**. Карточка показывает капитанов CT/T, таймер, доступные карты и историю банов. Капитаны банят карты по очереди. На каждый ход даётся **15 секунд**; если капитан не отвечает, бот автоматически ис��лючает случайную карту и передаёт ход. Последняя оставшаяся карта становится картой матча.

Текущий пул карт: **Sandstone, Province, Rust, Dune, Hanami, Breeze, Prison**.

Командные голосовые комнаты `CT` и `T` скрыты от обычных игроков: комнату видят только участники соответствующей команды, бот и администрация. Когда из комнаты выходят все игроки, запускается таймер на **1 минуту**. Если за это время никто не вернётся, комната автоматически удаляется; при возвращении игрока таймер отменяется и начнётся заново после следующего опустошения.

## Норматив квалификации

Стандарт квалификации — **K/D 1.00**. Команда `/standard` показывает норматив, текущий K/D, лигу и результат проверки. `/setup` также публикует эту команду и краткий стандарт в карточке канала `#команды`. Игрок проходит норматив, если его K/D не ниже значения `QUALIFICATION_KD`. Игроки лиг **Division** и **Pro** освобождаются от норматива автоматически. Проверка доступна командой `/qualification` и в дашборде через **Рейтинг → Норматив лиги**.

Лига определяется по ELO: Default до 1149, Qualifications от 1150, Division от 1350, Pro от 1600.

## Начисление рейтинга

- начальный рейтинг: `1000`;
